Section 06
Technical Observations & Remediation Status
✅
Options API in Reports.vue Resolved — R1

The Reports view was the only view using Options API (data(), methods:, mounted:). It has been migrated to Composition API with setup(), matching the rest of the codebase.

✅
Reports filters unwired Resolved — R1

Report endpoints existed but did not accept filter parameters. Backend updated to pass warehouse, category, status, and month through apply_filters() and filter_by_month(). Frontend now calls getCurrentFilters() and watches for changes.

✅
FilterBar case mismatch Resolved — R1

FilterBar was emitting lowercase option values ("delivered", "circuit boards") while data used title-case. Backend masked the issue with .lower(). Fix applied at the source: option values now match data capitalization exactly.

✅
Hardcoded nav text Resolved — R1

The Reports nav link in App.vue contained a hardcoded string instead of t('nav.reports'). Fixed; all six nav links now use i18n keys and switch correctly between English and Japanese.

⚠️
Demand forecast coverage gap Addressed in R2

Only 9 of ~30 inventory SKUs have forecast records. Restocking engine uses a heuristic fallback (reorder_point × 1.5) for uncovered items. Expanding forecast coverage is a data quality improvement outside current scope.

⚠️
No authentication layer Out of scope

The application has no login, session tokens, or role-based access. useAuth.js is a stub returning a hardcoded mock user. CORS is open (allow_origins=["*"]). Acceptable for internal demo; must be addressed before any public deployment.

⚠️
No data persistence By design

The backend loads JSON files once at startup. All mutations (tasks created, purchase orders placed) are lost on restart. Sufficient for a demo but not for production use — would require a database layer.

⚠️
No router lazy-loading Minor / optional

All 6 views are eagerly imported in main.js. With the current bundle size this is not a concern, but switching to defineAsyncComponent() would reduce initial load time as the app grows.

Development Setup & Key Ports
Start frontend
  • Working dir: client/
  • Command: npm run dev
  • URL: http://localhost:3000
  • Hot-reload via Vite HMR
Start backend
  • Working dir: server/
  • Command: uv run python main.py
  • URL: http://localhost:8001
  • API docs: http://localhost:8001/docs
Slash command shortcut
  • Type /start in Claude Code prompt
  • Kills existing processes on both ports
  • Starts backend then frontend in background
  • Defined in .claude/commands/start.md
